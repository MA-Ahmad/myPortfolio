# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Yarn is the package manager (`yarn.lock`).

- `yarn dev` — dev server on http://localhost:3000
- `yarn build` / `yarn start` — production build / serve
- `yarn lint` — ESLint (flat config, `eslint.config.mjs`)

There is no test suite. Type-check with `npx tsc --noEmit`.

`AGENTS.md` warns that this Next.js version (16.x) has breaking changes: read the relevant guide in `node_modules/next/dist/docs/` before writing Next-specific code.

## Architecture

**Pages Router** (not App Router), React 19, Tailwind 3, Framer Motion. Imports are rooted at the repo top level via `tsconfig` paths (`components/...`, `lib/...`, `data/...`, `themes/...`), not relative paths.

- **Layouts**: pages opt out of the default `AppLayout` by setting `Page.getLayout` (type `NextPageWithLayout` in `pages/_app.tsx`). `getLayout` does not receive page props, so `pages/themes/[theme].tsx` reads the theme from `useRouter().query`.
- **Content** lives in `data/` (`profile.ts`, `data.ts`, `projectData.ts`, `posts/*.mdx`). Blog lists merge local MDX with Dev.to articles (`lib/blogPosts.ts`, `lib/devto.ts`); only the 10 latest are served.
- **Themes** (`themes/`): alternate full-page versions of the portfolio (`terminal`, `notebook`), each exporting a `Home` and `Layout`. They are registered in `themes/registry.ts` and served by the single dynamic route `/themes/[theme]` (static paths, `fallback: false`, ISR driven by `contributionsRevalidate`). To add a theme, create `themes/<key>/` and list it in the registry. Each theme has its own content adapter (`content.ts`) and CSS module; the notebook theme draws its skyline and backdrop with three.js (`themes/notebook/lib/*`).
- **Theme Studio** (`/theme-studio`, `pages/theme-studio.tsx`, `components/canvas/*`, `lib/canvas/geometry.ts`): a node-canvas UI where dragging a wire from a theme card's port into the display node navigates to that theme. `components/canvas/nodes.ts` holds the card definitions and all layout constants (desktop vs. mobile layouts, port positions); `geometry.ts` has the pure wire/collision math. Adding a theme card means updating `CardId`/`CARDS` there plus a preview in `components/canvas/previews/`. `/canvas` redirects to `/theme-studio`. Visitors see each other's cursors and wires (`components/canvas/multiplayer.tsx`) through a Cloudflare Durable Object relay in `workers/presence/` (its own package and `wrangler.jsonc`, excluded from the site's tsconfig; deploy with `yarn deploy` there; its Cloudflare login is repo-local via `yarn cf:login`). The worker enforces the abuse limits that keep it inside the Cloudflare free plan: per-IP connection rate (rate-limit binding), per-IP connection cap, per-socket and per-IP message token buckets, per-IP and room-wide hourly budgets, with bans stored in Durable Object KV. The message protocol and validation shared by both sides live in `lib/canvas/presence.ts`. Positions are world coordinates and only peers on the same desktop/mobile layout are drawn; it is off without `NEXT_PUBLIC_PRESENCE_URL`.
- **Blocks** (`/blocks`, `/blocks/[category]`, `/blocks/[category]/[name]`): ready-made sections with a live preview and their source, modeled on chanhdai.com's blocks. A block lives in `blocks/<name>/` (entry `<name>.tsx`, default export), is described in `blocks/registry.ts` (`BLOCKS`; its `files` feed the Code tab, read and highlighted at build time by `lib/block-source.ts`) and loaded through `blocks/components.ts`. The viewer (`components/blocks/block-viewer.tsx`) shows it in an iframe of `/preview/[name]`, a bare page with no site layout. Category tabs and pages exist only for categories that have a block. `/blocks` routes use a wider column (`md:max-w-6xl`) via `AppLayout`.
- **Agent-readable markdown**: `/llms.txt`, `/about.md`, `/experience.md`, etc. are rewrites in `next.config.js` to `pages/api/agents/*`, generated by `lib/agent-markdown.ts`. Requesting `/` with `Accept: text/markdown` is rewritten to the same output.
- **Command menu** (`components/command-menu/`, cmdk): ⌘K / Ctrl K / `/`; includes the "Themes" group linking to theme pages.
- **Database**: Prisma + PostgreSQL only backs the `/api/posts` like/view routes (`lib/prisma.ts`). Env vars (`DEVTO_USERNAME`, `DATABASE_URL`, `IP_ADDRESS_HASH`, `GA_TRACKING_ID`, `MICROSOFT_CLARITY`) are listed in `README.md`.
- Light/dark theming via `next-themes` (class attribute, default light) with CSS variables in `styles/globals.css`.
