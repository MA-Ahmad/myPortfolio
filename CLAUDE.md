# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

pnpm is the package manager (`pnpm-lock.yaml`, pinned via `packageManager`; the presence worker has its own lockfile).

- `pnpm dev` — dev server on http://localhost:3000
- `pnpm build` / `pnpm start` — production build / serve
- `pnpm lint` — ESLint (flat config, `eslint.config.mjs`)

There is no test suite. `pnpm typecheck` runs `tsc --noEmit`. CI (`.github/workflows/ci.yml`) type-checks the site and the presence worker on every pull request; it also runs lint, which does not block yet because of existing errors.

`AGENTS.md` warns that this Next.js version (16.x) has breaking changes: read the relevant guide in `node_modules/next/dist/docs/` before writing Next-specific code.

## Architecture

**Pages Router** (not App Router), React 19, Tailwind 3, Framer Motion. Imports are rooted at the repo top level via `tsconfig` paths (`components/...`, `lib/...`, `data/...`, `themes/...`), not relative paths.

- **Layouts**: pages opt out of the default `AppLayout` by setting `Page.getLayout` (type `NextPageWithLayout` in `pages/_app.tsx`). `getLayout` does not receive page props, so `pages/themes/[theme].tsx` reads the theme from `useRouter().query`.
- **Content** lives in `data/` (`profile.ts`, `data.ts`, `projectData.ts`, `posts/*.mdx`). Blog lists merge local MDX with Dev.to articles (`lib/blogPosts.ts`, `lib/fetchPosts.ts`); only the 10 latest are listed. `/blog/[slug]` also serves every local MDX post, and redirects other old slugs to where the post lives now (local copy or Dev.to). Posts hosted on Dev.to set Dev.to as their canonical. `components/shared/meta.tsx` emits a self-referencing canonical on every page (pass `noindex` instead for pages that shouldn't be indexed); `/sitemap.xml` is `pages/api/sitemap.ts`.
- **Themes** (`themes/`): alternate full-page versions of the portfolio (`terminal`, `notebook`, `midnight`, `panorama`, `marginalia`), each exporting a `Home` and `Layout`. They are registered in `themes/registry.ts` and served by the dynamic route `/themes/[theme]` (static paths, `fallback: false`, ISR driven by `contributionsRevalidate`). A theme may also declare `pages` (midnight has `work` and `skills`), served at `/themes/[theme]/[page]` by `pages/themes/[theme]/[page].tsx` inside the same `Layout`. To add a theme, create `themes/<key>/` and list it in the registry. Next doesn't preload a dynamic route's own fonts, so a theme lists its font files in `themes/fonts.ts` and `pages/_document.tsx` preloads them, keeping text from rewrapping after first paint. Each theme has its own content adapter (`content.ts`) and CSS module; `midnight` is a dock-navigated dark theme (pixel headings, a click-to-run pipeline graphic, heatmap, experience rail); `panorama` is four sections on one torn sheet that weld shut as a section opens (`themes/panorama/torn/*`; a torn seam reaches for a nearby cursor with threads that can be pulled to weld it, `torn/tether.tsx`; a welded seam's threads pull it apart, `torn/strain.tsx`; while anything is pulled the mouse is drawn on the hand at the threads' end and the real cursor hidden, `torn/stick.ts`; threads on the sheet's top left corner lift it, and pulled far enough the sheet peels away to the other time of day as a view transition, `torn/peel.tsx` and `torn/peel-transition.ts` (its rules are in `styles/globals.css`); its night sky is a field of white grid pixels along the top (none by day), an ordered dither of drifting noise with a few cells flaring white-hot, `torn/pixel-field.ts`, set in `pixel-field.json`; on phones every seam stays welded, the moon stays in the Intro, and swiping on past the end (or top) of the open section opens the next (or previous) one, `components/sections.tsx`); `marginalia` is the whole site as one paragraph whose underlined phrases open notes in the margins, each joined to its phrase by a wire routed through the gutter (`themes/marginalia/components/paragraph.tsx` places them; both margins from 1280px, the right one from 880px, footnotes under the paragraph below that); the notebook theme draws its skyline and backdrop with three.js (`themes/notebook/lib/*`).
- **Theme Studio** (`/theme-studio`, `pages/theme-studio.tsx`, `components/canvas/*`, `lib/canvas/geometry.ts`): a node-canvas UI where a theme card is connected to the display node by a wire and opened from there. The visitor's own wire is a bundle of hairline strands with bands of light running down it, drawn on one canvas over the stage (`components/canvas/strands.tsx`, math in `lib/canvas/strands.ts`); other visitors' wires stay plain lines. Desktop and phone are the same carousel: the display sits above a row of theme cards (`ROW`, `slotOffset` in `nodes.ts`): the active one is in the slot under the display, joined to it by the bundle at rest; the display's body is a screen playing that theme's own page live in a scaled-down frame (`.screen` in `display-node.tsx`, laid out `PAGE_W` wide, so a phone's display shows the page's phone layout), scrollable like the page; clicking another card, the previous/next buttons or the arrow keys slides it in, with the bundle fading out for the slide and back in on the new one, and clicking the active card or the display's Open button sends it: a volley of light and sparks up the strands (`VOLLEY`, `SPARK_*`; timed by `SEND_*` in `canvas-stage.tsx`) while the display's screen shows a pixel progress bar in that theme's colours (`components/canvas/send-progress.tsx`, drawn by `lib/canvas/pixel-bar.ts`: the wire's colours for Classic, round green dots for Terminal, round blue dots for Panorama, highlighter yellow running into ink blue for Marginalia, four colourful segments for Midnight and Notebook), with the site's sections (Intro, Work, Articles, Blocks) listed under it filling in turn, each with its percentage (pointing at one picks its stretch out on the bar); the bar holds short of full until the page has loaded; once full the screen grows, the page fades up on it and opens. On desktop the display and the cards can be picked up and moved (a card by any part of it; a press that never travels stays a click), with the connected card kept below the display; the bundle keeps its full fan on both edges, stays lit, and its middle trails the move on a spring and settles (`SWAY_*`, `STIR_*` in `strands.tsx`). Turning the carousel puts moved nodes back. On a phone the nodes are not draggable: the neighbouring cards' edges show either side of the active one, and a sideways swipe on a card turns the carousel. `components/canvas/nodes.ts` holds the card definitions and all layout constants (desktop vs. mobile layouts, port positions); `geometry.ts` has the pure wire math. Cards are all one size (`CARD_W`, `PREVIEW_H`); the display's size is per layout (`displaySize`). Adding a theme card means updating `CardId`/`CARDS` and `ROW` there plus a preview in `components/canvas/previews/` (and a command menu entry; the studio dock, `components/shared/studio-dock.tsx`, plugs in only Terminal, Notebook and Midnight, `DOCK_THEMES`, to stay small). `/canvas` redirects to `/theme-studio`. Visitors see each other's cursors and wires (`components/canvas/multiplayer.tsx`) through a Cloudflare Durable Object relay in `workers/presence/` (its own package and `wrangler.jsonc`, excluded from the site's tsconfig; deploy with `pnpm deploy` there; its Cloudflare login is repo-local via `pnpm cf:login`). The worker enforces the abuse limits that keep it inside the Cloudflare free plan: per-IP connection rate (rate-limit binding), per-IP connection cap, per-socket and per-IP message token buckets, per-IP and room-wide hourly budgets, with bans stored in Durable Object KV. The message protocol and validation shared by both sides live in `lib/canvas/presence.ts`. Positions are world coordinates and only peers on the same desktop/mobile layout are drawn; it is off without `NEXT_PUBLIC_PRESENCE_URL`.
- **Blocks** (`/blocks`, `/blocks/[category]`, `/blocks/[category]/[name]`): ready-made sections with a live preview and their source, modeled on chanhdai.com's blocks. A block lives in `blocks/<name>/` (entry `<name>.tsx`, default export), is described in `blocks/registry.ts` (`BLOCKS`; its `files` feed the Code tab, read and highlighted at build time by `lib/block-source.ts`) and loaded through `blocks/components.ts`. The viewer (`components/blocks/block-viewer.tsx`) shows it in an iframe of `/preview/[name]`, a bare page with no site layout. Category tabs and pages exist only for categories that have a block. `/blocks` routes use a wider column (`md:max-w-6xl`) via `AppLayout`.
- **Redraw** (home page only; on `sm` and up the callout beside the MA mark, `components/portfolio/redraw-callout.tsx`; on phones the pencil-ruler button in `components/shared/top-nav.tsx`; also the command menu and `/?redraw=1`): a crew of agent cursors takes the page apart and draws it back. `lib/redraw.ts` holds the start event; `pages/index.tsx` loads `components/redraw/redraw.tsx` (overlay, rulers canvas, toolbar) only when asked. `components/redraw/scan.ts` turns the live DOM under `[data-redraw-scope]` (the `AppLayout` root) into layers (frame / media / text / wipe) without cloning anything; `engine.ts` runs the agents on springs in one rAF loop (its rulers live in the page's own hatched guide-rail gutters, `[data-redraw-rails]`, kept up for the whole run: a mirrored pair of page-height rulers, each box being drawn measured with a capped dimension line on the gutter nearer to it; none on narrow screens), hides layers with `data-rd` + `visibility` (rules in `styles/globals.css`) types text by shrinking a CSS Custom Highlight, and puts rows of capsules (skills, tags, icon buttons, a legend) and cell grids down item by item in reading order, fills the GitHub calendar week by week, and draws pictures through `media.ts` (inline SVG traced stroke by stroke with dashes, `<use>` swapped for plain stand-ins while drawn; rasters developed row by row through a soft mask and a blur-to-sharp filter; all inline styles stashed and restored). `sound.ts` is one soft synthesized sound (quiet panned plinks, a swell and two notes), toggled from the toolbar and remembered in `localStorage`; off by default. At the end the whole crew flies down into one tight, tilted flock on top of the toolbar (sunflower places, `FLOCK_SPACING`) and fades out with it when it closes. While the camera follows, agents only take work within `REACH` of the frontier, so sections are drawn in page order and in view. The press blanks the page at once (`data-redraw-pending`, before the chunk loads); the engine scrolls to the top and a damped camera follows the drawing frontier down the page until the visitor scrolls themselves (the toolbar's follow toggle hands it back). Elements marked `data-redraw-ignore` stay untouched and visible; `data-redraw-skip` (the callout, the spider and its webs) is hidden for the whole run and comes back at the end (`="fade"`, the callout, fades back in). Unmounting at any point restores the page.
- **Agent-readable markdown**: `/llms.txt`, `/about.md`, `/experience.md`, etc. are rewrites in `next.config.js` to `pages/api/agents/*`, generated by `lib/agent-markdown.ts`. Requesting `/` with `Accept: text/markdown` is rewritten to the same output.
- **Command menu** (`components/command-menu/`, cmdk): ⌘K / Ctrl K / `/`; includes the "Themes" group linking to theme pages.
- **Env vars**: `DEVTO_USERNAME`, `GA_TRACKING_ID`, `MICROSOFT_CLARITY`, `NEXT_PUBLIC_PRESENCE_URL` (Theme Studio presence; off without it). There is no database.
- Light/dark theming via `next-themes` (class attribute, default light) with CSS variables in `styles/globals.css`.
